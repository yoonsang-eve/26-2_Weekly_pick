# 주간 추천 에이전트 설계 (prompt v4~)

wk8부터 고정 프롬프트 체인 대신 쓰는 구조다. 코드는 `src/agent/`, 프롬프트는 `prompts/v4/`,
설정은 `config.yaml`의 `agent:` 블록에 있다.

## 1. 왜 바꿨나

| 문제 | 증거 | 새 구조의 대응 |
|---|---|---|
| 하락장에서 손실이 크다 | wk6 -9.8%, wk7 -16.2% | 국면을 먼저 판단하고 자세(aggressive / balanced / defensive / hedge)를 고른다. 단기채·현금성 ETF와 인버스 ETF도 고를 수 있다 |
| 스크리닝이 사실상 '고베타 베팅'이다 | 구 스크리너 후보 20종목 평균 vs 벤치마크: wk4 KR +5.6% vs +2.1%, wk5 KR +1.5% vs -0.8%, wk7 KR -13.5% vs -13.8%, **wk7 US -12.8% vs S&P500 -2.0%** | 고정 필터를 없앴다. 지표 패널만 주고, 어떤 조건으로 거를지는 에이전트가 국면을 보고 정한다 |
| 후보가 한 섹터에 몰린다 | KR 추천 wk4~6이 세 번 연속 반도체 밸류체인(티에스이·피에스케이홀딩스·SK스퀘어), wk7 최종 제출도 반도체 장비(LRCX) | 섹터 로테이션 도구, '서로 다른 관점 두 가지 이상으로 탐색' 지시, 같은 섹터 연속 선택 시 비교 근거 요구 |
| 에이전트라기엔 고정 체인이다 | analyst → bull → bear → trader가 항상 같은 순서로 1번씩 | 도구 사용 루프. 비판이 핵심을 무너뜨리면 후보 탐색으로, 국면 판단이 흔들리면 국면 조사로 되돌아간다 |
| 사람이 매번 돌려야 한다 | 스크리너·에이전트·정산·덱을 수동 실행 | 작업 스케줄러가 매시간 tick. 추천일과 보고일을 스스로 판단 |
| 지난 결과가 다음 판단에 안 쓰인다 | log.csv는 쌓이지만 읽히지 않는다 | 주차 종료 후 회고 → 교훈 장부. 과적합 방지 규칙 포함 (5절) |

과제 규칙은 그대로다: 매주 1종목, 평가 주간 첫 거래일 시가 매수 → 마지막 거래일 종가 매도, **주차별 수익률의
단순합**으로 순위. 단순합이라는 점이 설계의 출발점이다. 복리가 아니므로 변동성 자체에는 이득도 손해도 없고,
남는 것은 기대수익뿐이다. 그래서 '고변동성 선호'는 기대수익이 양일 때만 쓰는 수단으로 격하했다.

## 2. 흐름

```
[tick, 매시간]  src/agent/run.py tick  (작업 스케줄러 · agent_register.ps1)
   │
   ├─ 끝난 주차가 있나? (고른 종목 시장의 매도일 종가가 현지 시각으로 확정)
   │     → 정산(final_log·log·cohort) → 비교군 수익률 → 회고 LLM → 교훈 갱신 → 발표 자료 → 알림
   │
   └─ 다음 평가 주간 추천 시각인가? (첫 거래일 전날 = 일요일 또는 연휴 마지막 날, 18:00 이후)
         → 데이터 준비 (LLM 없음: KR 약 500·US 약 510 주식 패널, ETF, 지수·매크로, 유사 주간 통계)
         → 에이전트 루프 ↓ → 산출물 → final.json → 알림

에이전트 루프 (한 대화, 도구는 모델이 고른다)
   국면 조사   market_overview · track_record · web_search            → write_note(국면·자세)
   범위 결정   sector_rotation · screen_etfs
   후보 탐색   screen_stocks / screen_etfs (조건을 에이전트가 정함) · instrument_detail · web_search
   반박        request_critique  ── 별도 컨텍스트 비판자 LLM (웹 검색, 동의 금지, 대화 기록 못 봄)
   판단        fatal → 후보 탐색으로 / 국면 흔들림 → 국면 조사로 / minor → 제출
   제출        submit_recommendation ── 코드 검증 실패 시 거부 사유를 돌려주고 루프 계속
```

추천을 놓쳤을 때(PC 꺼짐)는 매수 시가가 아직 안 온 시장으로 따라잡는다. 예: 월요일 10시에 켜지면 한국장은
열렸으므로 미국만 후보로 남긴다.

## 3. 고정 체인에서 유지한 원칙

- **후보는 데이터에서 나온다.** LLM에게 "오를 종목을 말해 봐"라고 묻지 않는다. 학습 기억 속 유명주를 꺼내지
  말라고 프롬프트에 적었고, 제출 종목은 시세를 확인한 것이어야 코드 검증을 통과한다.
- **확증편향 대응.** Bull/Bear 분리는 '비판자 도구'로 옮겼다. 비판자는 별도 호출이라 메인 대화를 보지 못하고
  매수 논거 텍스트만 받는다 (CLAUDE.md 5절의 '컨텍스트 분리'와 같은 이유). 최종 종목은 비판을 받지 않으면
  제출이 거부된다.
- **검색으로 확인되지 않은 수치·일정 금지.** 메인·비판자 프롬프트 모두.
- **위생 필터.** 시총·거래대금 하한은 `screen_stocks`에 기본으로 걸린다. 고정 체인의 필터 1·2와 같은 값.
- **모멘텀/반전 구간 분리.** 패널 지표 `ret_mom`(t-140~t-20)과 `ret5`는 스크리너와 같은 정의다. 쓸지 말지를
  에이전트가 정할 뿐이다.

## 4. 도구

| 도구 | 내용 | 비고 |
|---|---|---|
| market_overview | 16개 지수·금리·환율·VIX·원자재 (1일~3개월, 이평선 괴리, 52주 고점 대비), 시장 폭, 과거 유사 주간의 다음 주 지수 분포(15년), 평가 주간 휴장·FOMC·사용자 일정 | base rate는 금→금 종가라 과제 규칙과 정확히 같지 않다고 명시 |
| sector_rotation | 업종별 중앙값 수익률(5·20·60일), MA20 위 비율, 섹터 ETF 상·하위 | KR 업종은 yfinance에서 받아 `data/kr_sectors.csv`에 캐시 |
| screen_stocks | 지표 13개 임의 구간 필터, 업종 포함/제외, 정렬 | 최대 30행 |
| screen_etfs | 태그(index·sector·foreign·bond_cash·inverse·leveraged·commodity) | KR은 상장 ETF 거래대금 상위 + 인버스·레버리지·현금성, US는 고정 58종 |
| instrument_detail | 지표 전체, 최근 10일 일봉, 12주 주간 종가, (US) 실적·배당락 예정일 | 패널 밖 종목도 조회 |
| track_record | 주차별 제출 종목·수익률·양 시장 벤치마크·당시 국면 판단, 회고 요약, 교훈 장부 | |
| write_note | 작업 메모 → `notes.md` | |
| request_critique | 비판자 LLM 호출 | 최대 4회, 1회당 검색 6회 |
| submit_recommendation | 최종 제출 | 검증: 제출 가능 시장, 시세 확인, 비판 여부, 국면 메모, 모든 제출 가능 시장 스크리닝 여부, 필수 항목과 형식(게이트웨이가 스키마를 강제하지 않는다), 현금성 ETF면 현금 아닌 후보 4개 이상 검토 |
| web_search | 서버 도구 (`web_search_20250305` 기본형) | 실행 전체 15회, 응답 1회 5회. 동적 필터링형(_20260209)은 wk8에서 내부 코드 실행이 실패해 쓰지 않는다 |

## 5. 피드백과 과적합 방지

표본이 주당 1개라 '지난주 반도체로 잃었으니 반도체를 피하자'는 노이즈 학습이다. 그래서:

1. 회고(`prompts/v4/review.txt`)는 **운과 실력을 분해**하고(시장 전체 움직임 vs 종목 선택), 같은 주의 비교군
   (탈락 후보, 지수 ETF, 인버스, 현금성 ETF) 수익률을 같이 본다.
2. 새 교훈은 주당 최대 2개, **과정 교훈(process)을 우선**한다. 결과 일반화는 금지.
3. 교훈마다 지지·반증 주차를 센다. 순지지 3주 미만은 **가설**로만 보여 주고 행동을 바꾸지 말라고 적는다.
4. 원자료 표를 교훈과 같이 준다. 에이전트가 교훈을 원자료로 다시 확인할 수 있게.

장부: `data/agent_lessons.json`. 주차별 회고: `outputs/wk{N}/agent/review.{md,json}`.

## 6. 산출물

`outputs/wk{N}/agent/`: `decision.json`(결정 전문), `transcript.md`(턴별 작업 기록), `notes.md`,
`critique_{n}_{티커}.md`, `rendered_system.txt`, `run_meta.json`, 회고 후 `review.*`.

기존 소비자(정산·cohort·발표 자료·데스크·자동 매매)가 고치지 않고 읽도록, 고른 시장 폴더에 기존 형식도 쓴다:
`pick.json`(스키마 동일 + regime/stance), `screen_meta.json`, `candidates.csv`(에이전트가 상세 조회한 종목),
`responses/bull.md`·`bear.md`·`agent.md`, `run_meta.json`. `final.json`은 `decided_by: agent`로 쓰되, 사용자가
직접 정한 값은 덮어쓰지 않는다. 발표 자료는 에이전트 주차를 감지해 2·3·4·5·8번 슬라이드 문구를 바꾼다.

## 7. 비용과 안전장치

- 루프는 매 턴 대화 전체를 다시 보낸다. system과 마지막 user 메시지에 캐시 표시를 달아 앞부분은 캐시 읽기로
  과금되게 했다. 장부(`llm_spend.jsonl`)는 캐시 읽기를 0.1로 가중해 센다 (`cache_read_weight`).
- **추천 1회 비용 상한 `agent.cost_limit_unit` = 4.0 unit** (메인 루프 + 비판자, 모델 단가로 실시간 계산). 70%에서 새 탐색을 멈추고 제출하라고 지시하고, 100%에서 중단한다. Letsur 게이트웨이를 20명이 월 200 unit으로 나눠 쓰는 사정에 맞춘 값이다.
- 주차 상한 `agent.token_budget` (입력 1.5M 가중 · 출력 200k). 넘으면 다음 호출이 거부된다.
- 턴 30, 검색 15, 비판 4. 남은 예산을 매 도구 결과 끝에 붙이고, 3턴 남으면 제출을 재촉한다.
- 모델은 세 역할 모두 Sonnet 5.5, 메인 루프만 effort medium. wk8 실측: 14턴 · 검색 7 · 비판 4 · 약 1.8 unit · 7분.
- 처음 쓰기 전 `python src/agent/run.py check`로 게이트웨이가 클라이언트 도구 호출을 중계하는지 확인한다
  (2026-10-18 확인: 서버 검색과 클라이언트 도구 모두 중계된다. 단 스키마 강제는 안 된다).

## 8. 일정·알림·화면

- **휴장일·대형 일정**: 토·일 첫 tick에서 앞으로 5주를 웹 검색으로 갱신한다 (`src/agent/calendar_refresh.py`,
  `prompts/v4/calendar.txt`, 약 0.1 unit). 휴장일은 손으로 적은 표에 더해지기만 하고, 바뀌면 알림을 남긴다.
  대형 일정은 `market_overview`의 '평가 주간' 항목과 데스크 캘린더에 나온다.
- **알림**: 메일 없이 `private/notify.jsonl` + Windows 알림. 데스크 '에이전트' 화면(추천·결과·오류)과
  '매매' 화면(체결·오류)이 기록을 보여 준다.
- **데스크**: '에이전트' 탭이 기본 화면이다. 스케줄(다음 추천·보고·마지막 tick), 작업 흐름 도면(단계별 횟수와
  되돌아간 경로), 턴별 기록, 결정, 비판 원문, 메모, 회고, 교훈, 다가오는 일정, 알림. 같은 주차를 여러 번 돌렸으면
  이전 실행도 고를 수 있다. 고정 체인 화면은 '이전 데스크 v3' 탭으로 남아 있다.

## 9. 실행

```bash
python src/agent/run.py status            # 이번 평가 주간·추천 예정 시각·결정 여부
python src/agent/run.py tools-test        # LLM 없이 데이터·도구 시험
python src/agent/run.py check             # 게이트웨이 도구 중계 확인 (LLM 소량)
python src/agent/run.py recommend         # 지금 추천 (LLM)
python src/agent/run.py review --week 8   # 정산 → 회고 → 발표 자료 (LLM)
python src/agent/run.py calendar          # 휴장일·대형 일정 갱신 (LLM + 검색)
powershell -ExecutionPolicy Bypass -File agent_register.ps1   # 매시간 tick 등록
```
