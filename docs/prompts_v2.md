# 프롬프트 전문 v2

`prompts/v2/*.txt`에 그대로 들어가는 원본. 동시에 수업 사이트 제출본의 소스다.
수정 시 이 파일을 덮어쓰지 말고 `prompts_v3.md`를 새로 만든다.

## v1에서 바뀐 것

1. **시장 컨텍스트 블록 추가.** `{{market_label}}` / `{{market_notes}}`가 들어갔다.
   KR·US 두 시장을 같은 프롬프트로 돌리되, 통화 단위·공시 출처·거래시간·가격제한폭처럼
   판단에 실제로 영향을 주는 차이는 주입해 준다.
2. **`{{ref_date}}` 추가.** 후보 표 지표의 기준일을 프롬프트에 명시한다. US는 시차 때문에
   기준일이 달력상 금요일이 아닐 수 있어, 그 사실을 모르면 LLM이 없는 가격을 가정한다.
3. **`{{search_policy}}` 추가.** 웹 검색 도구 사용 가능 여부에 따라 지침이 달라진다.
   v1은 "웹 검색으로 확인하라"가 하드코딩되어 있어, 검색이 없는 실행에서 LLM이 확인한 척
   지어내는 문제가 있었다.
3-1. **`{{holding_days}}` 추가.** v1은 "5영업일"이 문구에 박혀 있었다. 휴장이 끼면
   시장마다 영업일 수가 달라진다 — 2026 추석 주간이 KR 3영업일 / US 5영업일이다.
   보유 기간이 판단 기준의 전제이므로 틀린 숫자가 박혀 있으면 전 단계가 어긋난다.
4. **trader의 `market` 필드 고정.** 시장별로 파이프라인이 독립이므로 출력 JSON의 `market`을
   그 실행의 시장으로 못박는다.

프롬프트의 판단 기준·역할 분리·제약 조건은 v1과 동일하다.

## Placeholder 규약

| 변수 | 주입되는 값 |
|---|---|
| `{{week_no}}` | 주차 번호 |
| `{{market}}` | `KR` 또는 `US`. 이 실행이 어느 시장의 파이프라인인지 |
| `{{market_label}}` | 시장 표시명 (`한국 (KOSPI / KOSDAQ)` / `미국 (S&P 500 + Nasdaq 100)`) |
| `{{market_notes}}` | 시장별 특성 블록. 통화 단위, 공시 출처, 거래시간, 가격제한폭 유무 등 (`config.yaml`의 `markets.{시장}.notes`) |
| `{{buy_date}}` | 매수일 (월요일 시가) |
| `{{sell_date}}` | 매도일 (그 주 마지막 거래일 종가). **시장별로 다를 수 있다** — 한쪽 시장만 휴장하는 주가 있다 |
| `{{holding_days}}` | 보유 영업일 수. 휴장이 끼면 시장마다 달라진다 (예: 2026 추석 주간은 KR 3영업일 / US 5영업일) |
| `{{ref_date}}` | 후보 표 지표의 기준일. US는 시차 때문에 달력상 금요일이 아닐 수 있어 스크리너가 데이터에서 확정한 날짜가 들어간다 |
| `{{today}}` | 프롬프트 실행일 |
| `{{candidates_table}}` | Step 1이 출력한 후보 20종목 표 (markdown). 금액 단위는 시장 통화 기준으로 변환되어 들어간다 |
| `{{macro_calendar}}` | 평가 기간에 걸리는 매크로 일정 (FOMC·금통위·옵션만기 등). 실행 전 수동 확인 |
| `{{search_policy}}` | 그 실행에서 웹 검색 도구를 쓸 수 있는지에 따라 달라지는 지침. 검색이 불가하면 "확인 불가는 확인 불가로 표기하라"는 문구가 들어간다 |
| `{{analyst_output}}` | Analyst 단계의 응답 전문 |
| `{{bull_output}}` | Bull 단계의 응답 전문 |
| `{{bear_output}}` | Bear 단계의 응답 전문 |


주입되는 실제 값은 다음과 같다.

**KR**

```
- 가격·시가총액 단위는 원이다. 시총과 거래대금은 억원으로 표기했다.
- 공시는 DART(dart.fss.or.kr) 원문으로 확인한다. 정규장은 09:00~15:30 KST.
- 가격제한폭이 ±30%다. 상한가 직행 시 추격 매수가 불가능한 점을 고려하라.
- 수급 확인 시 기관·외국인 순매수, 공매도 잔고, 대차잔고를 본다.
- 매수일이 한국 휴장일이면 그 주 첫 영업일 시가가 매수가다.
```

**US**

```
- 가격·시가총액 단위는 USD다. 시총은 10억 달러($B) 단위로 표기했다.
- 실적 발표는 ET 기준 날짜와 장전(pre-market) / 장마감 후(after-hours) 구분까지
  확인하라. 5영업일 구간에서 이 구분이 수익률 부호를 바꾼다.
- 공시는 SEC EDGAR(8-K, S-1, 424B5, 13D/G) 원문으로 확인한다. 정규장은
  09:30~16:00 ET.
- 가격제한폭이 없다. 갭 상승·갭 하락이 KR보다 크므로 하방 시나리오를 더 크게 잡아라.
- 섹터 로테이션과 금리(10Y), 달러인덱스 민감도를 반드시 확인하라.
- 미국 공휴일(휴장)에 매수일이 걸리면 다음 영업일 시가가 매수가다.
- 한국시간 금요일 기준으로는 미국 현지 금요일장이 아직 열리지 않았다. 스크리너가
  출력한 '기준일'이 곧 확정된 마지막 종가일이며, 그 이후 가격은 모른다는 전제로 쓴다.
```


`{{search_policy}}`에 들어가는 두 값은 다음과 같다.

**웹 검색 가능**

```
웹 검색 도구를 사용해 사실을 직접 확인하라. 검색으로 확인되지 않은 수치·일정은 쓰지 않는다.
```

**웹 검색 불가** (게이트웨이가 검색 툴을 중계하지 않는 경우)

```
이 실행에서는 웹 검색 도구를 쓸 수 없다. 따라서 네 학습 데이터에 없는 최신 사실은 알 수
없다고 전제하라. 날짜·수치·일정을 지어내지 말고, 확인이 필요한 항목은 전부 "확인 불가
(검색 도구 없음)"로 표기한 뒤 그 불확실성을 판단에 반영하라.
```

검색 가능 여부를 프롬프트에 정직하게 알리는 것이 이 치환의 목적이다. 검색이 없는데
있는 것처럼 물으면 LLM이 날짜와 수치를 지어낸다.

가격 지표의 기준일은 {{ref_date}} 종가다.

## 작업

1단계. 각 종목에 대해 최근 3주간의 뉴스·공시를 확인하고 아래 테이블을 채워라.

| 종목 | 최근 상승 원인 | {{buy_date}}~{{sell_date}} 예정 catalyst | 가격 반영 정도 | {{holding_days}}영업일 내 하방 리스크 |

작성 규칙:
- 확인된 사실만 기재한다. 확인되지 않으면 "확인 불가"로 적고, 추측으로 채우지 않는다.
- 날짜와 수치는 출처와 함께 적는다. 기억에 의존한 수치는 쓰지 않는다.
- "가격 반영 정도"는 뉴스 발표 시점과 그 이후 주가 반응을 근거로 판단한다.

2단계. 아래 항목을 반드시 개별 확인하고 해당하면 명시하라.
- 평가 기간 중 실적 발표 예정 여부 (시각과 장전/장후 구분까지)
- 유상증자·전환사채·보호예수 해제 등 물량 출회 공시
- 배당락, 액면분할, 지수 편출입
- 매크로 이벤트 노출도 (금리 민감, 환율 민감, 유가 민감 등)

3단계. 위 결과를 근거로 후보를 3개로 압축하라.

압축 기준:
- {{sell_date}} 이전에 실현될 수 있는 구체적 catalyst가 있을 것
- 장기 성장 스토리, 밸류에이션 매력, 업종 전망은 판단에 사용하지 않는다
- "이미 많이 올랐다"는 이유만으로 배제하지 않는다. catalyst의 잔여 여력으로 판단한다
- 탈락시킨 종목은 각각 한 줄로 탈락 사유를 남긴다

출력은 1단계 테이블 → 2단계 체크 결과 → 3단계 압축 결과 및 탈락 사유 순으로 한다.
```

## 판단 기준

1순위: {{sell_date}} 이전에 실현 가능한 catalyst의 구체성. 날짜가 특정되지 않은 catalyst는 없는 것으로 본다
2순위: 매도 측 반박이 매수 논거의 핵심을 무너뜨렸는지 여부. 주변부 반박은 감점하지 않는다

## 출력

먼저 3개 종목의 비교 논증을 서술하고, 마지막에 아래 JSON을 코드블록 없이 단독으로 출력한다.
market 값은 "{{market}}" 로 고정한다.

{
  "market": "{{market}}",
  "ticker": "",
  "name": "",
  "thesis": ["", "", ""],
  "catalyst": "날짜가 포함된 구체적 이벤트",
  "expected_return_range": [하한, 상한],
  "primary_risk": "",
  "rejected": [{"ticker": "", "reason": ""}, {"ticker": "", "reason": ""}]
}
```
