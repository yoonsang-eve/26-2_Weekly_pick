# 주간 종목 추천 프롬프트 (v2)

학기 전체에 고정으로 사용하는 프롬프트다. 매주 바뀌는 것은 `{{ }}` placeholder에 주입되는 값뿐이고, 프롬프트 문구 자체는 바뀌지 않는다. 특정 주차나 특정 종목에 대한 내용은 프롬프트에 포함하지 않는다.

- 프롬프트 버전: v2 (v1은 기록으로 보존)
- 스크리닝 설정 버전: config_version 3

## v1에서 바뀐 것

| 변경 | 내용 |
|---|---|
| 대상 시장 | KR 단독 → **KR + US 병행.** 시장별로 독립된 파이프라인을 돌려 각각 1종목을 추천한다 |
| 프롬프트 | 시장 컨텍스트 블록(`{{market_label}}`, `{{market_notes}}`), 기준일(`{{ref_date}}`), 검색 가능 여부 지침(`{{search_policy}}`) placeholder 추가 |
| 스크리닝 | US 유니버스(S&P 500 + Nasdaq 100)와 US 기준 임계값 추가. **필터 3·4의 파라미터는 두 시장이 동일** |
| 실행 방식 | 수동 붙여넣기 → **LLM API 직접 호출**(auto 모드). 수동 모드도 그대로 유지 |

필터의 종류와 판단 기준, 단계 분리 구조는 v1과 같다. 바뀐 것은 대상 시장의 범위와 실행 방식이다.

---

## 1. 파이프라인 개요

LLM에게 "다음 주에 오를 종목을 추천해줘"라고 묻지 않는다. 종목 후보는 기계적 스크리닝으로 먼저 확정하고, LLM은 그 후보 안에서만 탈락과 선택을 수행한다.

1. **Step 1 — 스크리닝 (LLM 호출 없음).** 가격·거래대금 데이터로 시장 전종목을 걸러 후보 20종목을 만든다.
2. **Step 2 — Analyst (LLM, 웹 검색).** 후보 20종목을 뉴스·공시로 검증해 3종목으로 압축한다. 이 단계는 **탈락만** 담당한다.
3. **Step 3 — Bull → Bear → Trader (LLM).** 매수 논거를 세우고(Bull), 그것을 반박하고(Bear, 웹 검색), 양측을 비교해 최종 1종목을 정한다(Trader). 이 단계는 **선택만** 담당한다.

단계를 쪼갠 이유는 세 가지다. (a) LLM에게 종목 스캔을 시키면 학습 데이터에 각인된 유명주나 이미 지나간 테마를 답하므로, 후보 확정은 반드시 실시간 가격 데이터로 한다. (b) 검증과 선택을 같은 호출에 두면 LLM이 먼저 마음에 든 종목의 변호인이 되어 나머지를 형식적으로 처리하므로 Step 2와 Step 3을 분리했다. (c) 단일 LLM 추천의 가장 큰 실패 모드가 확증편향이므로, Bear에게 "매수 측에 동의하지 말 것"을 명시적으로 강제한다.

**KR과 US는 위 3단계를 각각 따로 돈다.** 한 프롬프트에 두 시장 후보를 함께 넣으면 LLM이 "어느 시장이 나은가"를 따지기 시작하는데, 그것은 이 과제의 판단 기준(5영업일 내 catalyst의 구체성)과 무관한 축이다. 시장 간 비교는 파이프라인 밖의 문제로 둔다.

## 2. Step 1 — 스크리닝 기준 전문

**이 단계는 LLM 호출이 아니다.** 파이썬 스크립트가 가격 데이터에 아래 규칙을 그대로 적용한다.

이 기준을 제출본에 포함하는 이유는, "LLM에게 무엇을 물었나"의 절반이 "무엇을 후보로 주었나"에서 결정되기 때문이다. 이 기준이 없으면 아래 프롬프트만으로는 결과를 재현할 수 없다.

### 기준일과 데이터

- 기준일은 **매수일 직전 금요일 종가**다. 그 시점까지 확정된 데이터만 사용한다.
- **KR 데이터 소스는 FinanceDataReader.** (한국거래소가 2025-12-27부터 정보데이터시스템을 회원제로 전환해 pykrx로는 계정 없이 전종목 조회가 불가능해졌다. 종목 선정 로직은 데이터 소스와 무관하게 동일하다.)
- **US 데이터 소스는 yfinance.** 수익률은 분할·배당 조정된 종가로, 표시 가격과 거래대금은 미조정 종가로 계산한다.
- **US 기준일은 달력이 아니라 데이터에서 확정한다.** 한국시간 금요일에는 미국 현지 금요일장이 아직 열리지 않았다. 받아온 시세에서 다수 종목의 마지막 거래일을 찾아 그것을 기준일로 쓰고, 확정된 날짜를 프롬프트(`{{ref_date}}`)에 그대로 넣는다.

### 유니버스

**KR** — KOSPI + KOSDAQ 전종목에서 다음을 제외한다.

- 우선주 (종목명 말미 `우`/`우B` 등, 그리고 종목코드 끝자리가 0이 아닌 종목)
- 스팩(SPAC), 리츠, ETF/ETN/ELW
- 관리종목, 투자주의환기종목
- 거래정지 종목 (기준일 종가가 존재하지 않는 종목)
- KONEX 전체

**US** — S&P 500 + Nasdaq 100 합집합에서 다음을 제외한다.

- 복수 클래스 주식의 비주력 클래스 (GOOG/GOOGL, FOX/FOXA 등에서 20일 평균 거래대금이 작은 쪽)
- 기준일 종가가 존재하지 않는 종목 (거래정지·신규상장)

구성종목 목록은 정적 CSV로 관리하고 분기 1회 갱신한다. 매주 새로 긁으면 지수 편출입이 조용히 스크리닝 결과를 바꿔 재현이 깨지기 때문이다.

### 필터

적용 순서대로다. **필터 3과 4의 파라미터는 두 시장이 동일하다.** 시장별로 다르게 둘 문헌적 근거가 없고, 다르게 두면 두 추천이 같은 기준으로 만들어졌다는 주장이 무너진다.

**필터 1 — 유동성.** KR은 20일 평균 거래대금 상위 300위 이내, US는 20일 평균 거래대금 5,000만 달러 이상.
알파를 노린 필터가 아니라 위생 필터다. 거래정지 리스크와 작전주를 피하고 발표 시 방어 가능한 종목만 남기는 목적이다. KR은 전종목이 대상이라 상대 순위로, US는 대형주 지수가 대상이라 절대 금액으로 건다.

**필터 2 — 시가총액.** KR 2,000억원 이상, US 20억 달러 이상. 목적은 필터 1과 같다.
US는 S&P 500 / Nasdaq 100 구성종목이 대상이라 이 하한이 사실상 비구속적이며, 시가총액 조회에 실패한 종목은 탈락시키지 않고 통과시킨다. 조회 실패를 탈락으로 처리하면 그 자체가 의도치 않은 필터가 되기 때문이다.

**필터 3 — 중기 모멘텀 + 단기 반전.** 아래 두 조건을 **모두** 만족.

- 모멘텀(순방향): `기준일 20영업일 전 종가 / 기준일 140영업일 전 종가 - 1` 이 상위 40% 이내
- 반전(역방향): 최근 5영업일 수익률 ≤ 0

이 필터가 스크리너의 핵심 설계다. 수익률의 자기상관은 측정 구간에 따라 부호가 뒤집힌다. 3~12개월 구간에서는 모멘텀이 순방향으로 작동하지만(Jegadeesh & Titman 1993), 1개월 이내 구간에서는 단기 반전이 지배한다(Jegadeesh 1990, Lehmann 1990). 이 과제의 보유 기간이 정확히 1주일이므로 "지난주 급등주를 사는" 단순 전략은 문헌상 오히려 역효과다.

그래서 **두 지표를 서로 겹치지 않는 구간에서 측정한다.** 모멘텀은 최근 20영업일을 건너뛴 120영업일 구간에서 재고, 반전은 그와 겹치지 않는 최근 5영업일에서 잰다. 모멘텀 측정 시 최근 1개월을 건너뛰는 것은 Jegadeesh & Titman의 표준 관행(skip-month)이며, 건너뛰는 이유가 바로 그 구간을 단기 반전이 지배하기 때문이다. 한 구간에서 두 조건을 동시에 걸면 두 효과가 상쇄되거나 부호가 거꾸로 붙는다.

**필터 4 — 변동성 정렬.** ATR20 / 종가 기준 내림차순 정렬 후 상위 20종목.

이것은 컷이 아니라 **정렬 기준**이며, 알파 팩터가 아니다. 오히려 반대다. 저변동성 이상현상 / betting-against-beta(Frazzini & Pedersen 2014)에 따르면 고변동성 종목의 위험조정수익률은 낮다. 그럼에도 고변동성을 선호하는 이유는 이 과제의 평가 구조 때문이다. 매주 독립 시행이고 손실이 다음 주로 이월되지 않아 복리 손실(geometric drag)이 없으므로, 변동성을 낮출 구조적 이유가 없다. 기대수익률을 깎는 대신 주간 상위권 진입 확률을 올리는 의도적인 선택이다.

### 제거된 필터 — 52주 신고가 근접

초안에는 "52주 신고가 대비 -10% 이내"(George & Hwang 2004) 필터가 있었으나 제거했다. (a) 해당 논문의 검정 구간은 6~12개월 보유이고 5영업일 구간에서의 증거가 없다. (b) 같은 논문의 핵심 주장이 "52주 고점 근접도가 과거 수익률 모멘텀을 대체한다"는 것이므로, 필터 3과 함께 하드 컷으로 걸면 같은 신호를 이중으로 세는 셈이 된다. (c) 실제로 지수가 고점 대비 크게 하락한 국면에서 이 필터는 돌파 임박 종목이 아니라 방어 업종만 통과시켜, 기술적 필터가 아니라 사실상 업종 필터로 작동했다.

현재는 필터가 아니지만 52주 고점 대비 하락폭은 후보 표에 참고 지표로 계속 제공한다.

### 출력

시장별로 위 기준을 통과한 상위 20종목. 각 종목에 대해 아래 값을 함께 넘긴다.

거래소 / 티커 / 종목명 / 업종 / 종가 / 시가총액 / 20일 평균 거래대금 / 6개월 모멘텀(최근 1개월 제외) / 20일 수익률 / 5일 수익률 / 52주 고점 대비 하락폭 / ATR20 대비 종가 비율

금액 단위는 해당 시장의 통화로 표기한다 (KR 원·억원, US 달러·$B·$M).

## 3. Placeholder 규약

아래 프롬프트의 `{{ }}` 부분에 매주 주입되는 값이다.

| 변수 | 주입되는 값 |
|---|---|
| `{{week_no}}` | 주차 번호 |
| `{{market}}` | `KR` 또는 `US`. 이 실행이 어느 시장의 파이프라인인지 |
| `{{market_label}}` | 시장 표시명 (`한국 (KOSPI / KOSDAQ)` / `미국 (S&P 500 + Nasdaq 100)`) |
| `{{market_notes}}` | 시장별 특성 블록. 통화 단위, 공시 출처, 거래시간, 가격제한폭 유무 등 (`config.yaml`의 `markets.{시장}.notes`) |
| `{{buy_date}}` | 매수일 (월요일 시가) |
| `{{sell_date}}` | 매도일 (그 주 마지막 거래일 종가). **시장별로 다를 수 있다** — 한쪽 시장만 휴장하는 주가 있다 |
| `{{holding_days}}` | 보유 영업일 수. 휴장이 끼면 시장마다 달라진다 (예: 2026 추석 주간은 KR 3영업일 / US 5영업일) |
| `{{ref_date}}` | 후보 표 지표의 기준일. US는 시차 때문에 달력상 금요일이 아닐 수 있어 스크리너가 데이터에서 확정한 날짜가 들어간다 |
| `{{today}}` | 프롬프트 실행일 |
| `{{candidates_table}}` | Step 1이 출력한 후보 20종목 표 (markdown). 금액 단위는 시장 통화 기준으로 변환되어 들어간다 |
| `{{macro_calendar}}` | 평가 기간에 걸리는 매크로 일정 (FOMC·금통위·옵션만기 등). 실행 전 수동 확인 |
| `{{search_policy}}` | 그 실행에서 웹 검색 도구를 쓸 수 있는지에 따라 달라지는 지침. 검색이 불가하면 "확인 불가는 확인 불가로 표기하라"는 문구가 들어간다 |
| `{{analyst_output}}` | Analyst 단계의 응답 전문 |
| `{{bull_output}}` | Bull 단계의 응답 전문 |
| `{{bear_output}}` | Bear 단계의 응답 전문 |


주입되는 실제 값은 다음과 같다.

**KR**

```
- 가격·시가총액 단위는 원이다. 시총과 거래대금은 억원으로 표기했다.
- 공시는 DART(dart.fss.or.kr) 원문으로 확인한다. 정규장은 09:00~15:30 KST.
- 가격제한폭이 ±30%다. 상한가 직행 시 추격 매수가 불가능한 점을 고려하라.
- 수급 확인 시 기관·외국인 순매수, 공매도 잔고, 대차잔고를 본다.
- 매수일이 한국 휴장일이면 그 주 첫 영업일 시가가 매수가다.
```

**US**

```
- 가격·시가총액 단위는 USD다. 시총은 10억 달러($B) 단위로 표기했다.
- 실적 발표는 ET 기준 날짜와 장전(pre-market) / 장마감 후(after-hours) 구분까지
  확인하라. 5영업일 구간에서 이 구분이 수익률 부호를 바꾼다.
- 공시는 SEC EDGAR(8-K, S-1, 424B5, 13D/G) 원문으로 확인한다. 정규장은
  09:30~16:00 ET.
- 가격제한폭이 없다. 갭 상승·갭 하락이 KR보다 크므로 하방 시나리오를 더 크게 잡아라.
- 섹터 로테이션과 금리(10Y), 달러인덱스 민감도를 반드시 확인하라.
- 미국 공휴일(휴장)에 매수일이 걸리면 다음 영업일 시가가 매수가다.
- 한국시간 금요일 기준으로는 미국 현지 금요일장이 아직 열리지 않았다. 스크리너가
  출력한 '기준일'이 곧 확정된 마지막 종가일이며, 그 이후 가격은 모른다는 전제로 쓴다.
```


`{{search_policy}}`에 들어가는 두 값은 다음과 같다.

**웹 검색 가능**

```
웹 검색 도구를 사용해 사실을 직접 확인하라. 검색으로 확인되지 않은 수치·일정은 쓰지 않는다.
```

**웹 검색 불가** (게이트웨이가 검색 툴을 중계하지 않는 경우)

```
이 실행에서는 웹 검색 도구를 쓸 수 없다. 따라서 네 학습 데이터에 없는 최신 사실은 알 수
없다고 전제하라. 날짜·수치·일정을 지어내지 말고, 확인이 필요한 항목은 전부 "확인 불가
(검색 도구 없음)"로 표기한 뒤 그 불확실성을 판단에 반영하라.
```

검색 가능 여부를 프롬프트에 정직하게 알리는 것이 이 치환의 목적이다. 검색이 없는데
있는 것처럼 물으면 LLM이 날짜와 수치를 지어낸다.

## 5. 사용 모델 및 도구

| 단계 | 모델 | 웹 검색 |
|---|---|---|
| Analyst | Claude Sonnet 5 | 사용 |
| Bull | Claude Sonnet 5 | 미사용 |
| Bear | Claude Sonnet 5 | 사용 |
| Trader | Claude Opus 5 | 미사용 |

실행 방식은 두 가지이고, 어느 쪽이든 프롬프트 문구와 산출물 형식은 동일하다.

- **auto** — LLM API(OpenAI Chat Completions 호환 게이트웨이 또는 Anthropic Messages API)로 4단계를 순차 호출한다. 각 단계에 실제로 사용된 모델과 토큰 사용량은 실행 메타데이터로 기록한다.
- **manual** — 렌더링된 프롬프트를 Claude 웹 인터페이스에 붙여넣고 응답을 저장한다. 게이트웨이가 웹 검색 도구를 중계하지 않는 경우 Analyst·Bear 단계만 이 방식으로 돌릴 수 있다.

**네 단계는 각각 독립된 호출(또는 별도의 새 대화)에서 실행한다.** 대화 히스토리를 누적하지 않고, 이전 단계의 응답 텍스트만 위 placeholder로 주입한다. Bear가 Bull과 같은 대화 맥락에 있으면 반박하지 않고 동조하는 경향이 있어, 컨텍스트를 물리적으로 분리하기 위한 조건이다. 프롬프트 문구와 동등하게 중요한 실행 조건이므로 함께 기재한다.

웹 검색을 쓸 수 없는 실행에서는 `{{search_policy}}`가 그 사실을 프롬프트에 명시한다. 검색이 없는데 있는 것처럼 지시하면 LLM이 날짜와 수치를 지어내기 때문이다.

Step 1 스크리닝에는 LLM을 사용하지 않는다.
